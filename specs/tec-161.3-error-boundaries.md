**Dependencies:** None

**Partially implemented in this heartbeat.** The CTO created:

**Remaining for Frontend Lead:** Wire the ErrorBoundary into any non-wizard pages that need it (dashboard, admin panel). Verify the "Retry" button properly resets step state.

## Problem

Zero error boundary wrapping. Any render crash in a wizard step (e.g., invalid Zod schema, missing API data) takes down the entire wizard with a white screen. Users see nothing and cannot recover.

## Scope

- `packages/ui/src/components/vehicle-step.tsx`
- `packages/ui/src/components/owner-step.tsx`
- `packages/ui/src/components/config-step.tsx`
- `packages/ui/src/components/offers-step.tsx`
- `packages/ui/src/components/checkout-step.tsx`
- `packages/ui/src/components/thank-you-step.tsx`
- `packages/ui/src/components/wizard.tsx` (if it orchestrates steps)

## Requirements

1. Create a reusable `ErrorBoundary` component in `packages/ui/src/components/error-boundary.tsx`
   - Accepts `fallback?: ReactNode` prop
   - Accepts `onError?: (error: Error) => void` for logging
   - Displays a localized friendly message with a "Retry" button
   - Catches `componentStack` and logs to console

2. Wrap each wizard step in the error boundary
3. Add a top-level error boundary around the entire Wizard component

4. Error boundary fallback should include:
   - User-friendly message in the current locale
   - "Încearcă din nou" / "Try again" button that resets the step
   - Optional "Raportează eroarea" / "Report error" link

## Acceptance Criteria

- [ ] Each wizard step is independently wrapped in ErrorBoundary
- [ ] A crash in one step does not affect other steps
- [ ] "Retry" button triggers step re-mount
- [ ] Error is logged to console
- [ ] Fallback UI is localized (RO/EN)
- [ ] Existing wizard functionality is preserved
